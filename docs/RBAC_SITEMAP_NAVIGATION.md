# نقشه‌سایت جامع و جریان ناوبری پنل مدیریت کلینیک دکتر زمانیان (RBAC Sitemap & Navigation Flow)

این سند مرجع فنی، معماری ناوبری، ساختار دسترسی نقش‌محور (Role-Based Access Control - RBAC) و جزئیات رندرینگ پویای منوی کناری (Dynamic Sidebar Rendering) را برای سامانه مدیریت و پرتال بالینی **«کلینیک تخصصی و فوق‌تخصصی زنان و زایمان دکتر مرضیه زمانیان»** تبیین می‌نماید.

---

## ۱. جدول کلی دسترسی نقش‌ها به ماژول‌های سیستم (RBAC Matrix)

در این سیستم، ۳ نقش اصلی با تفکیک وظایف دقیق (Separation of Duties - SoD) و بر اساس اصل کمینه‌سازی اختیارات (Principle of Least Privilege - PoLP) تعریف شده‌اند:

| شناسه ماژول (`id`) | نام ماژول فارسی | مسیر روت (`route`) | دسته‌بندی | مدیر کل (Super Admin) | مدیر پذیرش (Receptionist) | ویرایشگر محتوا (Content Editor) | مجوزهای عملیاتی (CRUD) |
| :--- | :--- | :--- | :--- | :---: | :---: | :---: | :--- |
| `dashboard` | **داشبورد اصلی** | `/admin/dashboard` | هسته اصلی | **نمایش کامل** | **نمایش متناسب** | **نمایش خلاصه** | خواندن آمارهای مجاز، مشاهده وضعیت روز |
| `calendar` | **نوبت‌دهی و شیفت پزشکان** | `/admin/shifts` | بالینی / پذیرش | **نمایش کامل** | **نمایش و ویرایش** | *مخفی (Hidden)* | ایجاد/ویرایش شیفت، لغو و تغییر نوبت‌ها |
| `patients` | **پرونده بیماران (EHR)** | `/admin/patients` | بالینی تخصصی | **نمایش کامل** | *مخفی (Hidden)* | *مخفی (Hidden)* | خواندن/نوشتن پرونده، ثبت سونوگرافی و دستورات HCG |
| `embryology` | **واحد جنین‌شناسی (IVF)** | `/admin/embryology` | آزمایشگاه ART | **نمایش کامل** | *مخفی (Hidden)* | *مخفی (Hidden)* | ثبت درجه بلاستوسیست، رصد تانک ازت N2، فریز تخمک |
| `messages` | **صندوق پیام‌های تماس** | `/admin/messages` | ارتباطات | **نمایش کامل** | **نمایش و پاسخ** | *مخفی (Hidden)* | خواندن پیام‌های مراجعین، ارسال پیامک پاسخ، بایگانی |
| `cms` | **مدیریت محتوا و مقالات** | `/admin/cms` | روابط عمومی | **نمایش کامل** | *مخفی (Hidden)* | **نمایش و ویرایش** | نگارش مقالات، انتشار اطلاعیه‌ها، ویرایش درباره ما |
| `financial` | **گزارش‌های مالی و بیمه** | `/admin/financial` | مالی و مدیریت | **نمایش کامل** | *مخفی (Hidden)* | *مخفی (Hidden)* | مشاهده درآمد سیکل‌های IVF، سهم بیمه تکمیلی |
| `security` | **لاگ‌های امنیتی (Audit)** | `/admin/security/logs` | امنیت سایبری | **نمایش کامل** | *مخفی (Hidden)* | *مخفی (Hidden)* | زنجیره رمزنگاری وقایع، لاگین‌های مشکوک، قفل IP |
| `settings` | **تنظیمات سیستم** | `/admin/settings` | زیرساخت | **نمایش کامل** | *مخفی (Hidden)* | *مخفی (Hidden)* | آستانه قطرهای فولیکول، سامانه ارسال خودکار پیامک |

## ۲. دیاگرام ناوبری و نقشه‌سایت تفکیک‌شده (Sitemap Trees)

### ۲.۱. جریان ناوبری نقش مدیر کل (Super Admin - دکتر زمانیان)
مدیر کل به تمامی ۹ ماژول، کلیه داده‌های بالینی محرمانه و وقایع حساس دسترسی نظارتی و عملیاتی دارد:

```
[ورود دومرحله‌ای 2FA / TOTP Authenticator]
                  │
                  ▼
         [پنل مدیریت مدیر کل]
                  │
  ┌───────────────┼───────────────┬────────────────┬───────────────┐
  ▼               ▼               ▼                ▼               ▼
[داشبورد اصلی] [نوبت‌دهی و شیفت] [پرونده‌های EHR] [جنین‌شناسی IVF] [صندوق پیام‌ها]
  │               │               │                │               │
  ├─ شاخص‌های روز ├─ تقویم هفتگی  ├─ سونوگرافی     ├─ نمونه‌های OPU├─ استعلام نوبت
  ├─ هشدار HCG    ├─ شیفت پزشکان  ├─ ضخامت آندومتر ├─ گرید بلاستو  ├─ مشاوره ناباروری
  └─ وضعیت اتاق‌ها└─ رزرو نوبت    └─ چرخه دارو     └─ مخازن ازت    └─ پاسخ پیامکی
                  │
  ┌───────────────┴───────────────┬────────────────┬───────────────┐
  ▼                               ▼                ▼               ▼
[مدیریت محتوا CMS]            [گزارش‌های مالی]    [لاگ‌های امنیتی]  [تنظیمات کلینیک]
  │                               │                │               │
  ├─ ویرایش درباره ما             ├─ درآمد پکیج IVF├─ زنجیره هش SHA├─ آستانه تریگر HCG
  ├─ اطلاعیه تعطیلات              ├─ بیمه تکمیلی   ├─ تلاش‌های ناموفق└─ کلیدهای API پیامک
  └─ مقالات آموزشی                └─ یارانه باروری └─ تغییر شیفت‌ها
```

### ۲.۲. جریان ناوبری نقش مدیر پذیرش (Receptionist / Staff)
پذیرش تنها به مدیریت مراجعین، تقویم کاری پزشکان و پیام‌های ورودی دسترسی دارد. دسترسی به پرونده‌های پزشکی، آزمایشگاه جنین‌شناسی، امور مالی و لاگ‌های امنیتی **به‌طور مطلق مسدود** است:

```
[ورود امن با رمز عبور قوی + SMS OTP]
                  │
                  ▼
        [پنل پرسنل و مدیر پذیرش]
                  │
        ┌─────────┴───────────────┬────────────────────────┐
        ▼                         ▼                        ▼
  [داشبورد پذیرش]          [نوبت‌دهی و تقویم شیفت]      [صندوق پیام‌های تماس]
        │                         │                        │
        ├─ تعداد نوبت‌های امروز    ├─ مشاهده ساعات کاری      ├─ بررسی سوالات مراجعین
        ├─ وضعیت اتاق‌های انتظار   ├─ جابجایی و لغو نوبت‌ها  ├─ ثبت پاسخ تلفنی/پیامکی
        └─ صف پذیرش حضوری         └─ ثبت حضور بیمار        └─ بایگانی درخواست‌ها
        
  [ماژول‌های مسدود/مخفی برای پذیرش]:
  ⛔ پرونده بیماران (EHR)     ⛔ جنین‌شناسی (IVF)        ⛔ گزارش‌های مالی
  ⛔ لاگ‌های امنیتی (Audit)    ⛔ تنظیمات سیستم           ⛔ مدیریت محتوا (CMS)
```

### ۲.۳. جریان ناوبری نقش ویرایشگر محتوا (Content Editor)
ویرایشگر محتوا صرفاً مسئول متون عمومی، مقالات آموزشی، و بخش‌های اطلاع‌رسانی وبسایت است. هیچ داده بیمار، تقویم شیفت یا جزئیات مالی در دسترس او نیست:

```
[ورود امن با محدودیت Session]
                  │
                  ▼
       [پنل ویرایشگر محتوا و رسانه]
                  │
        ┌─────────┴────────────────────────────────────────┐
        ▼                                                  ▼
  [داشبورد محتوا]                              [مدیریت محتوا و اخبار CMS]
        │                                                  │
        ├─ آمار بازدید مقالات                              ├─ ویرایش متن «درباره کلینیک دکتر زمانیان»
        ├─ آخرین پیش‌نویس‌ها                              ├─ درج اطلاعیه‌های تعطیلات و مناسبت‌ها
        └─ وضعیت انتشار                                   ├─ نگارش مقالات سلامت باروری و تغذیه
                                                           └─ مدیریت سوالات متداول (FAQ)

  [ماژول‌های مسدود/مخفی برای ویرایشگر]:
  ⛔ نوبت‌دهی و شیفت‌ها        ⛔ پرونده بیماران (EHR)     ⛔ جنین‌شناسی (IVF)
  ⛔ صندوق پیام‌های مراجعین    ⛔ گزارش‌های مالی          ⛔ لاگ‌های امنیتی
  ⛔ تنظیمات سیستم
```

## ۳. معماری پیاده‌سازی رندرینگ پویای سایدبار (Dynamic Sidebar Implementation)

رندرینگ سایدبار از الگوی اعلامی (Declarative Configuration) بهره می‌برد. روت‌ها و منوها هیچ‌گاه هاردکد نشده و پیش از رندر از فیلتر اعتبارسنجی عبور می‌کنند.

### ۳.۱. مدل داده ماژول‌ها و سطوح دسترسی (TypeScript Interface)

```typescript
// lib/clinic-mgmt-logic.ts
export type UserRole = 'SUPER_ADMIN' | 'RECEPTIONIST' | 'CONTENT_EDITOR';

export interface AdminModuleConfig {
  id: string;
  label: string;
  route: string;
  allowedRoles: UserRole[];
  category: 'core' | 'clinical' | 'communication' | 'management';
}

export const ADMIN_MODULES: AdminModuleConfig[] = [
  {
    id: 'dashboard',
    label: 'داشبورد اصلی',
    route: '/admin/dashboard',
    allowedRoles: ['SUPER_ADMIN', 'RECEPTIONIST', 'CONTENT_EDITOR'],
    category: 'core',
  },
  {
    id: 'calendar',
    label: 'نوبت‌دهی و شیفت پزشکان',
    route: '/admin/shifts',
    allowedRoles: ['SUPER_ADMIN', 'RECEPTIONIST'],
    category: 'clinical',
  },
  {
    id: 'patients',
    label: 'پرونده بیماران (EHR)',
    route: '/admin/patients',
    allowedRoles: ['SUPER_ADMIN'],
    category: 'clinical',
  },
  {
    id: 'embryology',
    label: 'واحد جنین‌شناسی (IVF)',
    route: '/admin/embryology',
    allowedRoles: ['SUPER_ADMIN'],
    category: 'clinical',
  },
  {
    id: 'messages',
    label: 'صندوق پیام‌های تماس',
    route: '/admin/messages',
    allowedRoles: ['SUPER_ADMIN', 'RECEPTIONIST'],
    category: 'communication',
  },
  {
    id: 'cms',
    label: 'مدیریت محتوا و اطلاعیه‌ها',
    route: '/admin/cms',
    allowedRoles: ['SUPER_ADMIN', 'CONTENT_EDITOR'],
    category: 'management',
  },
  {
    id: 'financial',
    label: 'گزارش‌های مالی و بیمه',
    route: '/admin/financial',
    allowedRoles: ['SUPER_ADMIN'],
    category: 'management',
  },
  {
    id: 'security',
    label: 'لاگ‌های امنیتی (Audit)',
    route: '/admin/security/logs',
    allowedRoles: ['SUPER_ADMIN'],
    category: 'management',
  },
  {
    id: 'settings',
    label: 'تنظیمات سیستم',
    route: '/admin/settings',
    allowedRoles: ['SUPER_ADMIN'],
    category: 'management',
  },
];

export function getVisibleSidebarModules(role: UserRole): AdminModuleConfig[] {
  return ADMIN_MODULES.filter((module) => module.allowedRoles.includes(role));
}

export function isModuleAllowed(moduleId: string, role: UserRole): boolean {
  const mod = ADMIN_MODULES.find((m) => m.id === moduleId);
  if (!mod) return false;
  return mod.allowedRoles.includes(role);
}
```

### ۳.۲. الگوریتم سوئیچ و مدیریت امن تب فعال در کامپوننت فرانت‌اند

هنگامی که کاربری با نقش خاص لاگین می‌کند یا نقش کاربر تغییر می‌کند، سایدبار منحصراً ماژول‌های مجاز را واکشی و رسم می‌کند. اگر تب فعال فعلی در محدوده مجاز نقش نباشد، به طور خودکار به تب امن `dashboard` بازمی‌گردد:

```typescript
// در سطح صفحه اصلی app/page.tsx
const handleRoleChange = (newRole: UserRole) => {
  setCurrentRole(newRole);
  // سد دفاعی: جلوگیری از ماندن کاربر در صفحه غیرمجاز قبلی
  if (!isModuleAllowed(activeTab, newRole)) {
    setActiveTab('dashboard');
  }
};
```

## ۴. لایه‌های امنیتی و گارد مسیرها (Route Guards & Defense-in-Depth)

1. **گارد سمت کلاینت (UI Guard):**
   سایدبار تنها آیتم‌های مجاز را نمایش می‌دهد. تلاش برای کلیک یا تغییر استیت به ماژول‌های قفل شده بلافاصله با صفحه خطای استاندارد `۴۰۳ - Forbidden` مواجه می‌شود.

2. **گارد سمت سرور (Next.js Middleware / API Routes):**
   مخفی بودن دکمه در سایدبار کافی نیست؛ در لایه سرور، توکن JWT کاربر حاوی ادعای نقش (`role: SUPER_ADMIN | RECEPTIONIST | CONTENT_EDITOR`) است.
   کلیه روت‌های زیر در سرور بلاک می‌شوند:
   - درخواست‌های مربوط به `/api/patients/*` برای هر نقشی غیر از `SUPER_ADMIN` با پاسخ `403 Access Denied` مسدود می‌شوند.
   - تغییر شیفت‌های پزشکان توسط `CONTENT_EDITOR` رد می‌گردد.
   - ارسال اطلاعیه CMS توسط `RECEPTIONIST` مسدود می‌گردد.

3. **سیاست انقضای نشست (Session Timeout - 15 Minutes):**
   جهت پیشگیری از سوءاستفاده افراد غیرمجاز در ایستگاه‌های کاری کلینیک، در صورت عدم فعالیت کاربر ظرف مدت ۱۵ دقیقه، نشست به صورت خودکار پایان یافته و کاربر به صفحه ورود هدایت می‌شود.

4. **ثبت غیرقابل تغییر در لاگ امنیتی (Audit Logging):**
   هرگونه تلاش برای دسترسی به روت‌های نامجاز با درج عنوان `UNAUTHORIZED_ACCESS_ATTEMPT`، همراه با آدرس IP، شناسه کاربر و زمان دقیق ثبت می‌شود.
